## Mock Architecture

### Core insight
Real Reanimated worklets receive the SharedValue as `this` context. The affordances
code uses the pattern `sv.value = withTiming(to, opts)`. In a JS mock, this calls
`withTiming(to, opts)` first, returning a config object, then assigns it to `sv.value`.
Detecting this assignment form requires a setter on `sv.value`.

### Solution: setter-based SV with `__anim` marker
- useSharedValue returns an object with a `value` property defined via Object.defineProperty
  whose setter intercepts values containing `__anim` (the marker from withTiming)
- withTiming always returns `{ __anim: { startTime, from, to, duration, easing } }`
- mockAnimState.tick(ms) iterates all SVs in `all` Set, looks up pending entry in
  `pending` Map keyed by SV reference, and computes interpolated value
- __advanceBy(ms) → tick(ms); __completeAll() → tick(1e12); __cancelAll() → clear pending

### jest.mock restriction
- jest.mock() factories can only reference module-scope vars prefixed with `mock` (Jest
  hoisting rule). Our module-level `mockAnimState` satisfies this.
- Global `MockReanimated` exposed via `(global as ...).MockReanimated = { ... }` after
  the factory so the test framework can drive the clock.

## Integration Test Status (floatingGitButton.test.tsx)
All 8 tests pass. Key findings from making the onQuickTap test pass:

1. `fireEvent.press` fires `onPress` (which calls `handleTap`). Using `pressIn`+`pressOut`
   does NOT trigger `onPress` — they are separate events. `handleTap` is wired to `onPress`,
   so `fireEvent(pressable, 'press')` is the correct trigger.

2. `reduceMotionResolved` starts `false` in FloatingGitButton. The
   `AccessibilityInfo.isReduceMotionEnabled()` Promise resolves asynchronously.
   Solution: render once, then `await act(async () => { await Promise.resolve(); })`
   to flush the microtask queue. This makes `reduceMotionResolved = true` before
   clock-controlled interaction.

3. `jest.useFakeTimers()` must be called AFTER the act() flush, not inside it.
   Calling render() inside nested act() causes "unmounted test renderer" errors.

4. jest.setup.ts does NOT configure fake timers globally — Jest uses real timers
   by default. Fake timers must be explicitly enabled per-test.
