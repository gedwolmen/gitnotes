# Task 3 Evidence - Mutual Exclusivity of AI Affordance State and Menu Transitions
# Generated: 2026-09-13

## Objective
Make AI affordance state (tap/new chat, long press/hub) and menu transitions (pan/drag) mutually exclusive.

## Problem Statement
When a user presses the FloatingAIButton and starts a pan gesture BEFORE the 450ms long-press delay expires, the pan gesture's `onBegin` fires and calls `cancelAffordances()`. However, the `Pressable`'s native `delayLongPress` timer continues running. After 450ms from initial press, `onLongPress` fires and opens the menu, conflicting with the drag operation.

## Root Cause Analysis
1. `GestureDetector` wraps `Animated.View > Pressable`
2. Pan gesture's `onBegin` → `cancelAffordances()` (visual feedback only)
3. React Native's native `delayLongPress` timer is NOT cancelled
4. After 450ms, `onLongPress` fires → menu opens even though pan/drag is active

## Solution
Track pan gesture activation during a press cycle using a ref (`panBeganDuringPressRef`). When pan begins (`onBegin`), set ref to true. In `handleLongPress`, check ref and return early if pan was active, preventing menu open while still allowing haptic feedback.

## Key Design Decisions
1. Used `panBeganDuringPressRef` ref instead of shared value for synchronous JS check
2. `handleLongPress` still calls `handleHoldComplete()` for haptics even when pan active
3. `setPanBeganDuringPress(false)` called in `onFinalize` to reset for next touch cycle
4. No changes to `delayLongPress` - relies on gesture handler to consume touch before timer fires
