## iOS Release Build (xcodebuild)

### Command
```bash
$ xcodebuild -workspace GitNots.xcworkspace -scheme GitNots -configuration Release \
  -destination "platform=iOS Simulator,name=iPhone 17" build
```

### Result: FAILED (linker error)

```
ld: symbol(s) not found for architecture x86_64
...
"_uniffi_gitnotes_git2_fn_func_..."  referenced from:
    ... in libGitEngine.a[x86_64][4](GitNotesGit2.o)
```

### Root Cause Analysis

**The Issue:**
- `libgitnotes_git2.a` is compiled for **arm64 only**
- Xcode project is building for **x86_64 + arm64 (universal binary)**
- Linker cannot find x86_64 symbols in arm64-only library

**Verification:**
```bash
$ lipo -info modules/GitEngine/ios-local/rust/libgitnotes_git2.a
Non-fat file: modules/GitEngine/ios-local/rust/libgitnotes_git2.a is architecture: arm64
```

**NOT CAUSED BY FLOATING BUTTON CHANGES:**
- Floating button changes only modified TypeScript files (FloatingAIButton.tsx, useFloatingAIButtonPanGesture.ts, AppFloatingGitButton.tsx, etc.)
- No changes to GitEngine native module or Rust code
- This is a **pre-existing GitEngine build configuration issue**

**Additional observations:**
- `ios.forceStaticLinking: "[]"` property may affect native module linking behavior
- The arm64-only library was built locally on Apple Silicon machine
- CI/EAS builds compile from source using cargo/rustc (cross-compile to x86_64)
